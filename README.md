# Accessible Travel Business Performance Analysis

## Project overview

This portfolio project demonstrates a beginner-friendly, end-to-end data analysis workflow using **synthetic accessible-travel booking data**. It is designed around the kinds of tasks listed in an entry-level Data Analyst job description: organizing records, validating data, analyzing operational metrics, reporting findings, and documenting work clearly.

**Important:** This is an independent portfolio simulation. The dataset is fictional and is not Wheel the World's internal data. The results must not be presented as real company performance.

## Business question

How can a travel business use booking data to monitor booking performance, completed-booking revenue, cancellations, destination trends, customer ratings, and data quality?

## Project outcomes

The project includes:
- 180 synthetic raw booking records with intentional data quality issues.
- A cleaned CSV dataset with documented standardization and exclusion rules.
- A data quality log describing detected issues and actions.
- An Excel workbook with a summary dashboard, destination revenue table, monthly revenue table, booking-status counts, and charts.
- A metrics JSON file containing reproducible summary values.
- A written analysis and limitations.

## Tools

- Microsoft Excel or Google Sheets for inspecting data and reviewing dashboard outputs.
- Python 3.10+ for repeatable data cleaning and KPI calculations.
- CSV for portable datasets and JSON for a machine-readable metrics summary.
- Git and GitHub for version control and project sharing.

The core analysis script uses Python's standard library only; no third-party Python packages are required to run it. The provided Excel workbook was generated for convenience and can be opened in Microsoft Excel or compatible spreadsheet software.

## How to run in VS Code

### 1. Download and extract

Extract the project ZIP file, then open the `accessible-travel-analytics` folder in VS Code using **File → Open Folder**.

### 2. Confirm Python is installed

Open the VS Code terminal (**Terminal → New Terminal**) and run:

```bash
python3 --version
```

On Windows, try `py --version` if `python3` is not recognized. Install Python 3.10 or later if needed.

### 3. Run the analysis

From the project root, run:

```bash
python3 src/analyze_bookings.py
```

On Windows, use:

```powershell
py src/analyze_bookings.py
```

The script reads `data/raw/raw_bookings.csv`, then refreshes:
- `data/processed/cleaned_bookings.csv`
- `analysis/data_quality_log.csv`
- `report/sample_metrics.json`
- `report/business_insights.md`

It does not overwrite the raw input file.

### 4. Open the dashboard

Open `dashboard/accessible_travel_dashboard.xlsx` in Excel or a compatible spreadsheet application. Review the `Dashboard`, `Raw Data`, `Cleaned Data`, and `Quality Log` worksheets.

**Note:** The Python script refreshes the CSV, JSON, and Markdown analysis outputs. The Excel workbook is a prebuilt portfolio dashboard; it is not automatically regenerated by the script. If you change the source data, refresh or rebuild the workbook separately.

## KPI definitions

- **Cleaned bookings:** Number of records remaining after duplicate and essential-field checks.
- **Completed-booking revenue:** Sum of `booking_value` for records whose normalized status is `Completed`. Cancelled and pending bookings are excluded.
- **Average completed booking value:** Completed-booking revenue divided by the number of completed bookings.
- **Cancellation rate:** Number of cancelled records divided by all records in the cleaned dataset. Pending and completed records remain in the denominator.
- **Average valid customer rating:** Mean of non-missing ratings in the range 1–5. Missing or invalid ratings are not imputed.
- **Destination and monthly revenue:** Completed-booking revenue grouped by destination and booking month.

All revenue values are denominated in CAD for this demonstration. The currency is an assumption for the sample data, not a claim about any real company's accounting.

## Data quality rules

1. Keep the first occurrence of a duplicate `booking_id`; exclude later duplicate rows.
2. Parse `booking_date` as an ISO date. Exclude rows with invalid dates.
3. Trim destination whitespace and standardize capitalization. Exclude rows with missing destinations.
4. Convert `booking_value` to a number. Exclude rows with invalid or negative values.
5. Standardize `Complete` to `Completed`. Exclude unrecognized booking statuses.
6. Accept customer ratings only from 1 through 5. Convert missing or invalid ratings to blank and log the issue.
7. Retain missing `customer_id` values as blank and log the issue; they are not required for the booking-level KPIs in this project.

These are transparent demonstration rules, not universal rules. In a real business, decisions about exclusion, imputation, currency, refunds, and status definitions should be agreed with stakeholders and documented.

## Results and interpretation

Run the script to regenerate `report/sample_metrics.json` and `report/business_insights.md` from the raw CSV. The report describes the strongest destination and month by completed-booking revenue, the main KPI values, and the limitations of the sample.

Because the data is synthetic and randomly generated, the results are illustrative only. They cannot support conclusions about Wheel the World or the accessible travel market.

## Limitations and next steps

- Data is synthetic and small; it is not representative of actual customer behavior.
- No external data sources, production database, or live dashboard refresh are included.
- Revenue is simplified to the booking value of completed bookings; taxes, refunds, fees, and currency conversion are not modeled.
- Ratings may be missing and may be affected by response bias.
- A next iteration could add SQL queries, Power BI, automated tests, date filters, accessibility-type comparisons, and stakeholder-reviewed metric definitions.

## How to discuss this project in an interview

Explain the workflow from raw records to cleaned data, quality log, KPIs, and business recommendations. Be ready to explain why invalid dates and negative booking values are excluded, why invalid ratings are left blank rather than guessed, and how you would validate the same rules with a stakeholder before applying them to production data.

Describe it honestly as a self-directed project using synthetic data. Do not claim that the analysis uses company data or that recommendations have been implemented by a real business.
